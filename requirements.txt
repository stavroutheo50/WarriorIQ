# onnx arrives as an ultralytics dependency, which is happy with 1.17 - and
# 1.17 carries eleven known CVEs, all fixed by 1.21/1.22. None is reachable
# through WarriorIQ (onnx parses model files, and people upload video, not
# models), but the fix is free, so it is pinned here rather than left to
# whatever the transitive resolver picks.
#
# On Windows this needs `--only-binary :all:`, and it still fails with
# WinError 206 unless long paths are enabled or the install runs through a
# short path: onnx ships test data with names like
# test_attention_4d_with_past_and_present_qk_matmul_bias_3d_mask_causal_expanded,
# which no amount of care in this repo can shorten.
onnx>=1.22
# onnxruntime-gpu, pinned to a CUDA 12 build, and NOT alongside `onnxruntime`.
#
# rtmlib depends on plain `onnxruntime`, which is the CPU wheel. Installing it
# means RTMPose runs on the CPU no matter what `rtm_pose_device` says - which
# is what happened here for months: the config read "cuda", the log carried one
# warning line, and the model refined at 15.6 ms per person. Both packages
# install into the same `onnxruntime` package directory, so having both is
# unsupported and which one wins depends on install order.
#
# The version matters and is not "latest". Measured 2026-09-14:
#
#     1.27 - 1.29   built against CUDA 13.0   <- needs cublasLt64_13.dll
#     1.21 - 1.26   built against CUDA 12.8   <- what torch cu128 already ships
#
# This project is CUDA 12 throughout (torch 2.11.0+cu128, tensorrt_cu12), so a
# 1.27+ wheel silently falls back to the CPU. 1.26.0 is the newest that
# matches. Do not "upgrade" this without checking that table.
#
# Install with:  pip install --no-deps onnxruntime-gpu==1.26.0
# (--no-deps, or pip may pull the CPU wheel back in for rtmlib.)
#
# The DLL search path is the other half; see core/rtm_pose.py, which imports
# torch before building the session because the CUDA libraries live in
# torch/lib and are not otherwise findable.
onnxruntime-gpu==1.26.0
